# 技巧、难度与评分

本项目不使用试数来出题与评判，而是内置一套**人类技巧求解器**（`Sudoku.Core/LogicalSolver.cs`）：
按技巧难度从低到高反复扫盘，直到解完或卡住。难度、档位、提示、教程全部由它驱动。

## 一、已实现的技巧（23 种，等级 1~13）

| 等级 | 技巧 | 一句话原理 |
| --- | --- | --- |
| 1 | 唯一候选数 | 该格只剩一个候选数 |
| 2 | 隐藏唯一候选数 | 该数字在自己的行/列/宫里只剩一个可放位置 |
| 3 | 区块摒除（宫内指向 / 线内归属） | 某数字在宫内被锁在同一行/列，则该行/列的其他格不能再放它（反之亦然） |
| 4 | 显性数对 / 隐性数对 | n 个格只装 n 个数字（或 n 个数字只落在 n 个格），即可互斥排除 |
| 5 | 显性三数组 / 隐性三数组 | 数对的三格版本 |
| 6 | X 翼 / 剑鱼 / XY 翼 | 有限图案类：两行两列（三行三列）的对齐；或枢轴与两翼的双值格链 |
| 7 | X 链（单数字链）/ 远程数对 | 单一数字的强链交替成链；或一串只含同样两数的双值格用共轭对串起来 |
| 8 | XY 链 / 唯一矩形 / 带鳍 X 翼 | 双值格链；四格两行两列两宫的「双解陷阱」；X 翼多出几个同宫的鳍格 |
| 9 | 交替推导链（AIC）/ 带鳍剑鱼 | 强弱链任意交替的通用链；剑鱼版本的带鳍鱼 |
| 10 | BUG+1（双值通用坟墓） | 除一格以外全是双值格、每个数字在单元内恰好出现两次时，那格里出现三次的候选数就是答案 |
| 11 | ALS-XZ（准锁定集） | 两个「n 格 n+1 候选数」格组共享受限公共候选数，另一个公共候选数必落在其一 |
| 12 | Sue de Coq（双翼锁定集） | 行/列与宫的交叉格为核心，宫侧、线侧各补几格；两侧**各自**是锁定集时，两侧的候选数分别被关在各自那几格里 |
| 13 | ALS 链 / 连续环 | 多个 ALS 用受限公共候选数串成链；或强弱链交替成环且每个候选数正好一强一弱，据弱链删同单元同类候选数 |

每一步推导都带四类数据，界面与提示直接消费：**高亮格**、**待删除候选数**、
**强弱链列表**（起止候选数 + 强/弱 + 中文理由）、**逐条推导文本**（分段式提示逐步展示）。

### 防「高阶技巧退化成低阶」的实现约束

高阶技巧的形状很容易被低阶结构「碰巧满足」，这几条是硬性约束：

- **ALS-XZ** 不接受「两个双值格」这种退化情形；
- **ALS 链**要求相邻 ALS 不重叠；
- **连续环**要求跨至少 3 个不同格；
- **Sue de Coq** 要求两侧的格组都非空，且**每一侧各自**构成锁定集（见下面的规则坑）。

## 二、难度评分（SER 风格）

评分参照 Sudoku Explainer：每种技巧给一个基础分，链按长度、删除按数量小幅加成，
**整题取解题路径上最难的那一步**（不是各步相加），所以一题的分数就等于「最难的那一招值多少分」。

| 技巧 | 基础分 | 技巧 | 基础分 |
| --- | --- | --- | --- |
| 隐藏唯一候选数 | 1.5 | 交替推导链（AIC） | 7.5 |
| 唯一候选数 | 2.3 | BUG+1 | 8.5 |
| 区块摒除 | 2.6 / 2.8 | ALS-XZ | 8.6 |
| 显性数对 | 3.0 | Sue de Coq | 8.8 |
| X 翼 | 3.2 | ALS 链 | 9.0 |
| 隐性数对 | 3.4 | 连续环 | 9.2 |
| 显性三数组 | 3.6 | 远程数对 | 5.5 |
| 剑鱼 | 3.8 | 带鳍 X 翼 | 6.0 |
| 隐性三数组 | 4.0 | 唯一矩形 | 6.2 |
| XY 翼 | 4.2 | XY 链 | 6.5 |
| X 链 | 5.0 | 带鳍剑鱼 | 7.0 |

- 链每多一条链接 +0.1（最多 +1.0）；每多删一个候选数再 +0.1（最多 +0.4），最后四舍五入到 0.1。
- **纯逻辑解不动**（把已实现的技巧全用上仍推不出来）记 9.0，并归入专家档。
- 出题器会**优先选择「用已实现技巧能纯逻辑解完」的题目**，这样「提示」永远有技巧可用。

## 三、六个难度档位

| 档位 | 判定口径 | 典型评分 |
| --- | --- | --- |
| 简单 | 只需唯一候选数 / 隐藏唯一候选数（≤2） | 1.5 ~ 2.3 |
| 中等 | 需要区块摒除 / 数对（≤4） | 2.6 ~ 3.4 |
| 困难 | 需要三数组、X 翼、剑鱼、XY 翼（≤6） | 3.6 ~ 4.2 |
| 专家 | 需要链级技巧（X 链 / XY 链 / AIC，≥7），**但不需要**高阶技巧 | 5.0 ~ 7.5 |
| 大师 | 解题路径上**必须**用到高阶技巧（远程数对 / 唯一矩形 / 带鳍鱼 / BUG+1 / ALS / 连续环） | 5.5 ~ 9.5 |
| 十七数 | 题面恰好 17 个提示数（唯一解的理论下限）**且必须用到高阶技巧** | 6.4 ~ 9.2 |

档位判定看的是「解题路径上**用到过**哪些技巧」，由求解器单独记录
（`LogicalSolveResult.UsesAdvancedTechnique`），因此不依赖是否收集每一步细节。

**出题流程**：生成完整终盘 → 在保证唯一解的前提下挖洞（反复重排顺序多轮扫，直到挖不动）
→ 用技巧求解器评级 → 比目标档位更难就回填线索校准。

- 大师档额外做两件事：① 改用**非对称挖洞 + 4 次重挖取最深**，把线索压到 17~26 个，更容易逼出高阶技巧；
  ② 命中不了就换一道题重来（`maxAttempts: 200`，实测平均十几次尝试命中，通常 1 秒内出题）。
- 简单~专家四档相反：校准阶段会**主动回填线索**，保证这些档位不会需要大师档才该出现的高阶技巧。

## 四、十七数题型

### 为什么不能靠挖洞得到

随机挖洞挖不出 17 提示数题目。实测过的死路（都是本项目真跑出来的数据）：

- 单格变异（挪一个提示数到别处）：约 2500 次尝试，**0 次**得到唯一解；
- 从已有 17 数题「删一格 → 枚举解 → 补一个单例格」的精确推导：只得到 31 个候选，全部与原题几乎相同，评分清一色 2.3；
- 无目标模拟退火：约 10.7 万次迭代得到 54 个唯一解命中，**没有一道**高于 2.3。

所以走**内置母题 + 等价变换**：换数字、换行带/列带、带内换行换列、可选转置——
这些变换都保持解的个数、提示数个数与难度不变。

### 母题从哪来（可复现）

母题取自公开的 17 提示数全目录（`acs40/sudoku-17-clues` 里的 `d1783.zip`，49157 道）。
把它逐道评一遍难度（16 线程约 7.5 分钟）后统计：

| 分类 | 道数 |
| --- | --- |
| 总计 | 49157 |
| 用到高阶技巧 | 2932 |
| **纯逻辑能解完且用到高阶技巧（＝本档候选）** | **1915** |
| 纯逻辑解不完（更高阶或需试数） | 1107 |

> 关键事实：**绝大多数 17 数题其实是简单题**——49157 道里有 21932 道只用唯一候选数就能推完。
> 所以「17 个提示数」本身根本不代表难，本档因此额外要求「必须用到高阶技巧」。

按最难技巧分组，各取 4 道作为内置母题（共 24 道）：

| 母题用的技巧 | 级 | 评分 | 道数 |
| --- | --- | --- | --- |
| ALS 链 | 13 | 9.2 | 4 |
| ALS-XZ | 11 | 8.8 ~ 9.0 | 4 |
| BUG+1 | 10 | 8.6 | 4 |
| 唯一矩形 | 8 | 6.7 | 4 |
| 带鳍 X 翼 | 8 | 6.6 | 4 |
| 远程数对 | 7 | 6.4 | 4 |

`Sudoku.Core.Tests/SeventeenCluesTests.cs` 会在每次构建时逐条复核：
**恰好 17 提示数 + 唯一解 + 纯逻辑可解 + 必须用高阶技巧 + 评分 ≥ 大师档下限（5.5）**。
另有一条反向测试：一道只用唯一候选数就能推完的经典 17 数题**不允许**被评为「十七数」。

运行时只做便宜的三项校验（17 个提示数 + 唯一解，加上母题本身可解析），
因为逐道跑一次 ALS 链求解要好几秒，放在出题路径上不可接受——难度保证由测试离线把关。

### 提示会自动放宽技法上限

十七数题目会逼出 ALS 链（13 级）这一档，所以这一档的对局点「提示」时会**自动把
「提示技法上限」放宽到 13 级**，否则高阶提示会一直显示「没有找到可用技巧」。

## 五、实现踩过的坑（重要）

### Sue de Coq 的锁定集判定

网上常见写法是：**「宫侧格数 + 线侧格数 − 交叉格数 = 两侧合计候选数个数 ⇒ 这些格构成锁定集」**。
**这个写法是错的**：宫侧的格与线侧的格彼此不同族（例如宫侧的 R4C4 与线侧的 R5C2 既不同行也不同列），
可以同时填同一个数字，合计数相等推不出锁定集——据此删除会**删掉正确答案**（实测复现 5 例，
例如把正解 R1C5(7) 删掉）。

正确条件必须落在**每一侧**上：宫侧那组、线侧那组**各自**满足「格数 = 候选数个数」，
因为只有同侧的格才两两同族。本项目按后者实现，普查 985 次命中、失真 0 次。

另一个坑：**不能**用「两侧共有的候选数」推「它只能落在交叉格」。一个数字在盘上出现 9 次
（每行/每列/每宫各一次），「宫侧那组里有它」说的是宫里那一次、「线侧那组里有它」说的是线上那一次，
两者不是同一格（实测这么推会删掉正解 R2C3(7)、R1C5(7)）。

### 提示按什么算候选数

提示以规则推导为基础，再**扣掉玩家自己删掉的候选数**（取交集）。所以手动排除过候选数之后，
提示会跟着变：可能因此直接给出「唯一候选数」，也可能某个技巧暂时不再出现。
某格一个候选数标记都没有时按规则推导处理（关掉自动标记也不会让提示失效）。

> 注意：**填错的数字会让推导整体失真**，此时提示不可靠，遇到异常先撤销错误的落子。
