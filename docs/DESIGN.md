# 界面与交互设计笔记

这里记录「为什么界面长这样」以及踩过的坑。UI 是手写命令式代码（无 XAML），
棋盘用 `GraphicsView` + `IDrawable` 矢量绘制，所以布局尺寸全部由代码算出来并**定死**。

## 一、对局页布局

竖直方向从上到下：**顶部信息条 → 棋盘 → 状态栏 → 工具行 / 绘制面板 → 数字键盘（含 XY）**。

几条硬规则（都是被实测问题逼出来的）：

- **棋盘尺寸只在「提示」面板开合时变化**。点格子、点按钮、切绘制模式、状态栏文字变长变短，
  棋盘都不能动（实测：11 次连续操作下数字键「5」的下沿恒为 886；改之前进绘制模式会从 896 跳到 830）。
- **状态栏高度定死**：按「最长的一条状态文字在当前宽度下需要的高度」预留，宽度变了才重量。
  文字长短一律不影响布局。
- **工具行与绘制面板叠在同一个格子里**，容器高度取两者较高者；绘制面板同时压扁
  （去掉面板内那行说明——那句话本来由状态栏负责，按钮矮一点，色块横排放得下就一行、
  窄屏自动折两行），因此普通模式下也不会白白空出绘制面板的高度。
- **手机窄屏（宽度 < 520）**：上下两排工具按钮 42 → 36、数字键盘与 XY 54 → 46、状态栏字号 13 → 12、
  棋盘内边距 10 → 2；绘制模式收起数字键盘（绘图时不需要选格填数）；对局页不显示导航栏
  （`NavigationPage.SetHasNavigationBar(this, false)`），难度/用时/进度本来就在页内第一行。
  实测 400×800 窗口下棋盘从约 340 涨到 **400×400**（内容宽 404，只剩 2 px 边距），
  两排按钮之间的空当从 49 px 收到 6 px，且切模式棋盘仍不变。
- 棋盘宽度按「内容宽度 − 4 px」限制（阶段八的贴边规则）。

## 二、提示面板（底部让位式）

| 行为 | 说明 |
| --- | --- |
| 打开提示 | 数字键盘、内容工具、绘制面板整块隐藏，把底部让给提示（棋盘始终完整可见） |
| 面板高度 | **固定高度**：宽窗口约屏高 19%、手机竖屏约 13%，夹在 62~168 之间；超高时面板内滚动 |
| 点「收起」 | 高度降到约 9~11% |
| 关闭 / 返回 / 应用 | 底部按钮自动回来 |
| 自适应 | 宽度铺满、高度按屏幕给上限，不需要手动拖 |

> 为什么要固定高度：原来只设了「最大高度」，推导每多一行面板就长一点，棋盘跟着缩水、格子位置乱跳
> （实测同一步骤里枢轴高亮块的横坐标从第 1 步的 161 漂到第 6 步的 224）。改成定高后，
> 连续点「下一步」时面板底边恒为 1042、枢轴横坐标稳定在 237~250。

**分段式提示流程**（设置里「高阶提示」打开时）：

1. **列技巧**：把当前盘面所有可用技巧按等级列出来，各自带条数（例：`X 链（单数字链）（1 条）`）；
2. **选路径**：同一技巧可能有多个实例，逐条列出可读标签（例：`① 删除 R4C5(1)`），
   选中后**棋盘立刻画出这一步**并高亮相关格；
3. **看推导**：一次一行，按「下一步」推进；链级技巧逐条展示强链/弱链的理由，最后给结论；
4. **应用**：按钮变为「应用这一步」——落子类直接填入，删除类会先按当前盘面补好候选数标记再删，
   全部可撤销。

## 三、提示高亮分色与分步渐显

新增一层「标记」模型（`Sudoku.Core/HintMarks.cs`）：每个标记 = 「某格里的某个候选数 + 角色 + 出现的推导进度」。
角色决定颜色（浅色主题一律用深色，不用浅蓝这类在白棋盘上会糊掉的颜色）：

| 角色 | 含义 | 浅色主题 | 深色主题 |
| --- | --- | --- | --- |
| 结构 | 结构本体所在的格/候选数（鱼身、链上格） | `#B26A00` | `#FFC14D` |
| 候选数 A / B / C | 结构里的关键候选数，按数字分色（同数字同色） | `#1B7F3B` / `#C62828` / `#4527A0` | `#6EE787` / `#FF8A80` / `#B39DFF` |
| 鱼鳍 | 带鳍鱼的鳍格 | `#E65100` | `#FFB74D` |
| 结论·删除 | 可以删掉的候选数（圈起来打叉） | `#AD1457` | `#F48FB1` |
| 结论·落子 | 可以直接填入的数字 | `#00695C` | `#4DD0A5` |

每个标记带「第几步才出现」（数值＝提示面板里第几条推导，0 基），棋盘跟着「下一步」逐段亮起：

| 技巧 | 第 1 条推导 | 中间 | 最后一条 |
| --- | --- | --- | --- |
| XY 翼 | 只有枢轴的两个候选数 | 第 2 条：两翼里与枢轴共享的数字同色，两翼共有的 z 用第三色 | 第 6 条：同时看见两翼处 z 被品红圈叉 |
| X 翼 / 剑鱼 | 鱼身（基线上的候选数） | 第 2 条：覆盖线上同样含该数字的位置 | 第 4 条：可删除的候选数 |
| 带鳍 X 翼 / 剑鱼 | 落在覆盖线上的基准格 | 第 3 条：鳍格单独用橙色粗框标出 | 第 6 条：可删除的候选数 |
| 链类 / 远程数对 / 唯一矩形 / BUG+1 | 结构格，链上候选数按数字分色 | — | 结论 |

只有带鳍鱼必须由技巧自己给出鳍格（盘面字段里基格与鳍格本来混在一起、分不出来），
所以标记既支持技巧自带（带鳍鱼、X 翼/剑鱼、XY 翼），也对老技巧自动兜底推导。
标记只在高阶提示激活时绘制，关闭提示面板或点「应用这一步」（设置默认开）会立刻清空。

## 四、输入与高亮

- **数字锁定模式**：开启后点下方数字键即锁定该数字，盘面上它的位置与候选数一起高亮；
  此时点格子就是把该数字填进去。关闭后点格子，会用该格候选数高亮下方对应数字键。
- **锁定模式下点「已经是正确数字」的格子完全不作响应**（题目提示数或自己填对的都算）：
  否则会把锁定的数字覆盖上去，白白记一次错误。不填、不计错、不选中、不改状态栏——
  要点别的格先点空的，要改错填的格（填错的数字仍按原逻辑覆盖 / 同数字则擦掉）。
- **填完自动跳号**：锁定模式下某数字填满 9 个后，自动锁到下一个还没填完的数字（按 1→9 绕圈，
  已填满的跳过），状态栏提示「数字 N 已填满，自动切换到 M。」；全填满则取消锁定。
  跳号同时清除当前选中格，避免光标停在刚填完那格上看着像还锁着旧数字。
- **数字键下方小灰字**：显示「9 − 盘面上该数字的个数」，即还差几个。
- **XY 按钮**（数字键最右侧）：用青绿描边圈出**恰好只剩两个候选数**的格子（XY 翼 / 远程数对一眼可找），
  下方小字给出个数。它只与**当前锁定的数字键**互斥，不影响「数字锁定」开关。
- **开关类按钮用整块高亮代替「✓」**：笔记 / 自动标记 / 数字锁定 / 绘制 / 涂色激活时换成强调色并加粗
  （深色 `#2E5480`、浅色 `#BFD9F5`），文字保持原样；绘制面板的色块选中时改用描边。
- 界面上方只留「撤销」按钮：原来「重做」与「重开」只差一个字还挨着，容易误点，所以重做只用快捷键 `Y`。

## 五、绘制模式（涂色 + 强弱链）

- **涂色**：选颜色后点格子刷色，再点同一格同一色即擦掉；最后一格「无」是橡皮。
- **画链**：点一个候选数作为起点（状态栏报出如 `R3C5(6)`），再点另一个候选数即完成连线，
  可跨格也可同格；再点同一候选数取消起点。实线=强链、虚线=弱链（键盘 `K` 切换）。
- **箭头指向落笔方向**；线条颜色取自当前选中色（线条单独一套同色相、更醒目的颜色，不与格子底色糊在一起）；
  线宽刻意做细（约 2 px，箭头稍大），避免遮住途经格里的候选数。
- **画链用弧线**（设置默认开）：直线横跨好几格时会从沿途格子的候选数上压过去，
  所以把链画成一条二次贝塞尔——控制点落在中点垂直方向上，偏移 `链长 × 0.22`（封顶 `0.8 × 格宽 × 2`），
  实际弯曲幅度是它的一半。同格内的短链（≤ `0.75 × 格宽`）仍画直线，太短画弧反而更乱。
  虚线（弱链）的虚线间距沿着曲线走，箭头按曲线在终点的切线方向贴上去；线头仍在箭头前收住。
  几何计算放在 [`Sudoku.Core/LinkCurve.cs`](../Sudoku.Core/LinkCurve.cs)，由单元测试锁住，绘制层只管调用。
  关掉这个开关就退回直线。
- 涂色与连线都进同一套撤销栈并随存档保存；某格一旦填入数字，与它相关的连线自动清理。
- **优先级**：绘制模式下不显示选中格（不铺选中底色、不画选中框，点格子也不顺手选中）；
  涂色优先级**最高**，选中 / 行列宫 / 同类数字 / 冲突 / 提示底色都排在它后面，
  被选中的格子改用一圈描边表示。

## 七、验证方法

改动 UI 后用两类手段交叉验证，记录在 [`../CHANGELOG.md`](../CHANGELOG.md) 的各阶段条目里：

1. **UI 自动化（UIA）**：启动发布版 exe，用 `System.Windows.Automation` 找到按钮并 `Invoke()`，
   读控件几何（坐标、尺寸）与文本，核对布局是否稳定、按钮是否可用、状态栏文案是否正确。
2. **截图像素统计**：把窗口置顶并截图，统计特定颜色的像素数与包围盒，用来验证「高亮有没有画出来、
   有没有盖住别的层、关闭后有没有清干净」——例如同一提示框位置下棋盘区差约 23 万像素、
   强链蓝像素 0 → 3770。画链弧线也是这么验的：沿直线中点做竖直剖面，弧线模式下线条只在偏离中点
   26 px 处命中（预测弯曲量 53 px 的一半），关掉开关后命中位置变回 −1/0 px。
3. **存档核对**：读 `%LOCALAPPDATA%\...\current-game.json`，核对 `LevelValue` / `TechniqueLevel` /
   `PuzzleSdk`（数一遍提示数）等字段，确认界面显示与内部状态一致。

纯逻辑部分（技巧是否误删候选数、难度档位、教程卡点）全部由 xunit 单元测试锁住，
见 [`../Sudoku.Core.Tests`](../Sudoku.Core.Tests)。

## 八、已知限制与取舍

- **练习局不写存档**：专项练习走 `IsPractice` 分支，`SaveGame()` 直接返回，不会覆盖「继续上一局」。
- **重做没有界面按钮**，只有快捷键 `Y`（见上）。
- **带鳍剑鱼与 BUG+1 没有教程例题**：在 1800+ 道真实题面里一次都没出现，教程页对它们给出无例题的降级说明
  （23 种技巧里 21 种能开出专项练习）。
- **Sue de Coq 在实战路径上更像「多一条线索」**：40 道大师题、1597 个盘面状态下命中 985 次、失真 0 次，
  但样本里没有出现「低阶技巧全用尽、只剩 Sue de Coq 能推」的局面。
- 存档格式是 JSON 快照（`Preferences` + 文件），**没有版本号迁移机制**，跨大版本升级后旧存档可能读不出来。
